# Исправления ревью — 0.4.0

## Исправленные сценарии

1. Поля дочерних функций больше не используют позицию обхода HashMap как ID.
   ID строится из SHA-256 нормализованного Windows Instance ID; HID-интерфейсы
   аналогично используют свой путь, диски — идентичность узла. Исходные пути и
   серийники не записываются открытым текстом в ID поля. Нумерация подписей функций
   сортируется по ID; сохранённый выбор привязан к функции, а не её позиции.
2. «Все» хранит исключения. Снятие PID не выключает поля других устройств и будущих
   подключений. Старые настройки читаются; прежние позиционные function/interface/disk
   IDs удаляются, поскольку восстановить их физическую цель достоверно невозможно.
   Остальные выбранные поля сохраняются.
3. JSON/HTML всегда содержат состояние перечисления, ошибки и целостность descriptor
   blocks. Политика приватности скрывает свободный текст причин, но не факт ошибки,
   операцию и код. Галочки не могут скрыть неполноту снимка.
4. Поиск ищет также VID/PID, instance ID, пути, порт и значения собранных полей.
   Выбор переключается на подходящий результат; при отсутствии результатов справа
   не остаётся прежнее устройство. Подтверждение идентичности для сравнения сбрасывается.
5. История открывается общей кнопкой независимо от наличия устройств и фильтра.
   Ограничение длины журнала исправлено: остаются последние 128 записей после приёма
   снимка, даже если одно обновление добавляет несколько записей.

## UX

- Иерархический список строится по CM_Get_Parent / Windows ID, а не по названиям.
  Контроллеры, хабы и устройства представлены вместе; дубликат физического хаба
  объединяется с его сведениями топологии. Неполные/циклические связи не скрывают узлы.
- Подпись включает порт, вложенность — небольшой отступ. Это программная топология,
  не доказательство расположения разъёмов на корпусе.
- Пресеты «Подключение», «Питание», «Драйвер», «Дескрипторы»; галочка всей группы.
  Пресет выбирает подходящие поля текущего узла; «Все» распространяется и на новые поля.
- Дескрипторы разделены по интерфейсу, alt setting, endpoint/смещению блока.
  Основные поля идут первыми. Групповые заголовки в таблице включаются при большом
  наборе или повторяющихся подписях; базовый экран остаётся плотным.
- Состояния портов и отсутствующие значения имеют понятные подписи; сравнение
  больше не показывает Rust-значения Some/None.
- Экспорт начинается с предпросмотра: перечень узлов, сохраняемых и скрытых полей,
  ошибок, отдельная настройка идентификаторов. Предпросмотр использует копию снимка
  и маски: фоновое обновление не подменяет сохраняемые данные.

## Проверки

- Семь новых регрессионных тестов: выбор «всё кроме», совместимость настроек,
  стабильность ID, ошибки/приватность отчёта, поиск, дерево с дубликатами/циклами,
  отсутствие выбранного устройства в пустом снимке.
- 54 Linux-теста и 55 Windows-тестов; Clippy обеих платформ.
- Два последовательных Windows-сбора: 112/112 function ID сохранили соответствие
  имени функции; до исправления ревью обнаружило 92 изменения из 112.
- Сбор: 14 устройств, 16 узлов топологии, 106 блоков. VID/PID multiplicity,
  режимы и длины конфигураций совпали с сохранённым XML USBTreeView.
- UI Automation: отдельный журнал, предпросмотр, смена режима, дерево и галочки.
  Для поиска используется ввод клавиатурой: SetValue через текущий AccessKit
  не меняет текст, хотя UIA не возвращает ошибку. Это ограничение accessibility
  пути ввода; обычный ввод проверяется отдельно.

## Не относится к закрытым исправлениям

Прерывание зависшего драйверного вызова, загрузка прежнего raw-снимка, сравнение
произвольных полей и полный паритет USBTreeView остаются отдельными работами.
Физическое unplug/replug, все DPI, реальные камеры/аудиокарты не проверялись.
Сборщик остаётся read-only; новое название ещё не выбрано.
