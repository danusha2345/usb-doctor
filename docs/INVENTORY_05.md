# Обзор USB-подключений — 0.5.0

Основной экран — таблица подключённых устройств. По умолчанию включена группировка
по контроллерам и хабам. Кнопки +/− сворачивают ветку целиком; есть «Свернуть всё» и
«Развернуть всё». Пустые служебные ветки скрыты, но доступны отдельной галочкой.
Без группировки отображается плоский список; хабы можно включить отдельно.
Одна физическая составная USB-периферия занимает одну строку, известные функции
показаны вместе. Типы определяются из класса/активной конфигурации и HID capabilities;
неизвестная модель не угадывается.

## Колонки и ID

Таблица на egui_extras::TableBuilder, с виртуализацией строк и закреплёнными заголовками.
Границы колонок перетягиваются мышью. Ширины и видимость сохраняются в
`%LOCALAPPDATA%\UsbDoctor\inventory.json`; в «Вид / колонки» есть сброс ширин.
Строки фиксированной высоты 24 px. Длинный текст не переносится: полное значение
доступно по наведению и через копирование. При расширении колонок доступна
горизонтальная прокрутка. Таблица использует ширину окна.

Доступны тип/функции, режим USB, порт, USB Device Address, VID:PID и состояние.
USB Device Address берётся из `USB_NODE_CONNECTION_INFORMATION_EX.DeviceAddress`,
а не из номера порта. Проверены все 14 адресов первого снимка 0.5.0 против исходного
EX-ответа. Адрес может измениться при повторном перечислении; это не VID/PID и не
Instance ID. Контроллерам без адреса периферийного USB-устройства выводится «—».

Нажатие строки открывает подробности. VID:PID и Windows Instance ID копируются
из контекстного меню строки или кнопками в подробностях; серийный номер — отдельной
кнопкой, когда поле доступно. Выбор колонок не ограничивает сбор.

## Изменения подключения

- Добавление подсвечивается зелёным, удаление — красным. Отключённая строка временно
  остаётся на прежнем месте и явно помечена как последние известные сведения.
- Длительность подсветки задаётся пользователем (3–60 с, по умолчанию 10 с).
- Изменения определяются только между полными перечислениями одного источника.
  Ошибка или неполный сбор не превращаются в массовое «отключение».
- По умолчанию раскрывается нужная ветка и список прокручивается к изменившейся
  строке. Несвязанные свёрнутые ветки остаются закрытыми. Выбор другого устройства
  не перехватывается. Если открыты подробности/история, доступна кнопка показа события.
- При пакетном изменении выбирается одна строка детерминированно; подсвечиваются все.
  Для свёрнутого хаба сохраняется счётчик изменений дочерних устройств.
- Поиск раскрывает путь к найденным строкам временно. Автопоказ изменения при
  несовместимом поиске очищает фильтр с явным уведомлением.

Автообновление выполняется после PnP-события с объединением за 800 мс и раз в 15 с
для фонового обновления свойств. Нижней строки «Снимок / время» и строки «Обновляем…»
нет. В обычной GUI-сборке нет демо-переключателя или тестовых кнопок. Сообщения о
паузе/ошибке/неполноте сохраняются, чтобы прежние данные не выдавались за свежие.

## Один экземпляр и остановка сбора

Именованный Windows mutex удерживается GUI до выхода. Второй запуск в той же сессии
не создаёт окно и пытается поднять существующее. Имена portable EXE могут отличаться.
На стенде перед обновлением старое окно закрывается с проверкой процесса.

GUI читает USB через отдельный скрытый процесс. «Остановить сбор» завершает его,
приостанавливает автообновление и сохраняет предыдущие данные. Есть предел 90 с.
Windows Job Object с KILL_ON_JOB_CLOSE не оставляет сборщик после аварийного завершения
GUI. Временный файл приватного результата удаляется после завершения процесса;
вывод ограничен 32 MiB. USB reset/eject или изменение драйвера не выполняются.

## Проверки

68 тестов Linux и 70 Windows (включая fixture-процессы с ожиданием, отменой,
неверным результатом и ошибкой), Clippy обеих платформ, Windows release build.
Тестовый worker собирается только с feature `test-worker` и не входит в архив.
Демо для разработческих тестов доступно только в сборке с этим feature; в обычной
GUI-сборке нет режима демонстрации.

Реальная GUI-проверка на Home-PC:
- сворачивание/разворачивание и поиск;
- изолированная отмена реально запущенного сборщика;
- второй запуск завершился без нового окна;
- ширина первой колонки перетянута с 443 до 533,5 px, изменение записалось в настройки;
- демо, строка обновления и время снимка в итоговом интерфейсе отсутствуют.

Красное/зелёное состояния проверены на синтетическом подключении/отключении в раннем
GUI-прогоне и в тестах модели; физическое unplug/replug специально не выполнялось.
Программа получает последовательные наблюдения, а не непрерывную аппаратную трассу:
быстрый цикл между опросами или устройство без устойчивого ID может не различаться.
Не заявляется полный паритет USBTreeView или измерение физического состояния кабеля.

Источники API:
- https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbioctl/ns-usbioctl-_usb_node_connection_information_ex
- https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexw

## Произвольные поля и проверка заполнения

На основном экране есть явная кнопка «Поля / колонки…». Каталог составляется из всех
полученных полей устройств и узлов; поиск по названию, группе и ID. Любое поле можно
добавить отдельной колонкой, включая драйвер, Hardware IDs, питание, дескрипторы,
HID и свойства Windows. Заголовки/выбор сохраняются; для неприменимого поля — «—».
Пустая строка, реально возвращённая Windows, отображается как «Пустое значение»;
в raw JSON исходная пустая строка сохраняется. В подробностях остаётся прежний
независимый выбор полей. Экспорт из таблицы использует её колонки, а из подробностей —
маску подробных полей; ошибки и статус полноты включаются всегда.
