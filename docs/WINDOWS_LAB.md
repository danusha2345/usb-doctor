(PID 6076 на момент проверки); старые экземпляры и демо-окно закрыты.

## Фактический результат

- GUI и CLI успешно запущены на Windows; CLI exit 0.
- 14 подключённых USB-узлов и 16 узлов топологии.
- 13624 строк полей с учётом повторения данных дочерних функций;
  105 сырых блоков дескрипторов, 577 HID-записей.
- С USBTreeView 4.7.4 совпали мультимножества VID/PID, режимы соединения и длины
  Configuration + Other-Speed Configuration. Учтены одинаковые модели устройств.
- На SSP-хабе RX/TX — 10 Гбит/с, подтверждено отдельным IOCTL, а не выведено из имени USB.
- Перечисление завершено, глобальных ошибок 0. Недоступные необязательные запросы
  остаются в карточках, в том числе строковый запрос к хабу с D2. USBTreeView для
  того же хаба также сообщает ERROR_GEN_FAILURE и указывает D2.
- Панель выбора полей открыта на Windows; PID снят и возвращён, изменения записались
  в `%LOCALAPPDATA%\UsbDoctor\fields.json`. Весь снимок сохранился.
- Автотест различает UIA CheckBox и одноимённый текст таблицы. Первые попытки находили
  текстовый PID, поэтому они не считались успешной проверкой галочек.
- В итоговом 2-секундном интервале — 31.2 мс процессорного времени;
  Working Set 86.6 MiB. Это одиночный замер после UI-проверки, не универсальный бенчмарк.

## Повторная сверка

```sh
python3 scripts/compare_usbtreeview.py .scratch/live-release-final.json .scratch/tree-reference.xml
```

Скрипт выводит только агрегаты; реальные IDs/серийники остаются в raw-входах.
Live JSON/XML и снимки экрана не добавляются в Git. В [демо-изображении](design/compact-native-demo.png)
показаны вымышленные данные, отрисованные настоящим Windows EXE; посторонний рабочий
стол не захвачен, сохранена только клиентская область нашего окна.

Не проверены физическое unplug/replug во время опроса, все типы USB и отдельная
учётная запись вне Administrators. Полный функциональный паритет USBTreeView не заявлен;
точные источники и оставшиеся ограничения — [IMPLEMENTATION.md](IMPLEMENTATION.md).
