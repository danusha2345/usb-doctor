# Проверки Windows

Проверено на Windows 11 x64, build 26120. Windows 10 заявлена целевой системой,
но отдельного runtime-прогона Windows 10 пока нет. Адреса стенда, учётные данные,
локальные пути и исходные снимки USB не нужны для повторной сборки и не входят
в актуальную документацию.

## 0.6.1 alpha

- 86 тестов Windows и 84 теста Linux прошли; Clippy на обеих целях без предупреждений.
- Реальное окно проверено через Windows UI Automation: RU → EN → перезапуск → RU.
  Переводились Connections, USB address, Table fields и Session history.
- Выбор языка и порядок колонок сохранялись. Второй экземпляр завершался,
  активируя уже открытое окно. Перед заменой EXE прежнее окно закрывалось.
- При ширине 900 px обе полосы прокрутки оставались видимыми; у обрезанного текста
  одна подсказка. Проверены три темы, перестановка колонок и одна колонка USB-адреса.
- Снимки [RU](design/usb-glaz-ru.png) и [EN](design/usb-glaz-en.png) получены с реального
  приложения по запросу автора; серийные номера и Instance ID на них не показаны.

## Покрытие сборщика

Первичное сопоставление с USBTreeView подтвердило 14/14 VID/PID и режимов USB,
длины Configuration/Other-Speed. Отдельный аудит 15 устройств дал 45/45 совпадений
ключевых свойств с Get-PnpDeviceProperty. Эти прогоны относятся к конкретному
набору оборудования и не доказывают полное покрытие всех устройств/драйверов.

После оптимизации на неизменном наборе 14 устройств/16 узлов быстрый cache-only
проход занимал 1,35–2,73 мс; полный CLI с запуском и записью JSON — около 701 мс
против 1154 мс до оптимизации. Все 17 458 прежних ссылок на поля найдены в новом
снимке. Это не замер задержки от физического подключения до отрисовки.

Методика сопоставления: `scripts/compare_usbtreeview.py` принимает локальный
JSON программы и XML USBTreeView. Исходные диагностические файлы не публикуются.
