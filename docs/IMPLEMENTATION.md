# Реализация 0.3.0: полный снимок и компактный вывод

Дата: 2026-09-27. Windows 11 Home-PC (build 26120), тест через SSH и интерактивную сессию.

## Сбор и отображение разделены

Сборщик не принимает маску полей. Он получает доступные сведения, сохраняет полный
снимок, затем UI и экспорт строят проекцию по галочкам. Пресеты «Основное», «Все»,
«Ничего», поиск по названиям/ID, группы свойств и сохранение выбора между запусками.
Идентификаторы показываются локально; в отчёт они входят только по отдельной галочке.

## Какие данные собираются

- EX/EX_V2 и их исходные ответы, режим, флаги возможностей, текущая конфигурация,
  адрес/класс, VID/PID, bcdUSB/bcdDevice, EP0 и PipeList.
- Все ключи свойств, перечисленные Windows SetupAPI для узла: драйвер/дата/версия,
  производитель, PnP IDs, ContainerID, возможности, power data, location и другие.
  Неизвестные типы не отбрасываются: значение сохраняется в HEX.
- Родительская цепочка PnP и свойства дочерних функций, COM PortName, HID capabilities
  из кэша Windows (button/value caps и link collections включительно), physical disk numbers и доказанное сопоставление букв томов.
- Хабы/контроллеры отдельно: свойства Windows, корневой хаб, тип/возможности/порты,
  состояния пустых портов, connector properties и companion связи.
- Device, Device Qualifier, Other-Speed Configuration, все заявленные Configuration, interface/endpoint/IAD/SS companion,
  class-specific blocks, BOS, языки и строки, на которые ссылаются дескрипторы.
- SuperSpeedPlus lane information: raw RX/TX, число линий и подтверждённая скорость.
- Неизвестные дескрипторные блоки сохраняются целиком. Частично разобранное не выдаётся
  за полностью декодированное. Недоступные запросы записываются отдельно.

## Компактный интерфейс

Основной экран — плотная таблица «поле / значение», без больших диагностических
карточек. Отступы корневой панели 10 px вместо 28, строки списка 38 вместо 62,
межстрочный зазор таблицы 3 px. Объяснения и большие HEX-блоки раскрываются по запросу.
Панель галочек сначала раскрывает основные поля; большие технические группы свернуты.
Снятая галочка не удаляет данные и не инициирует повторный USB-опрос.

## Проверки на настоящей Windows

- CLI завершился с exit 0: 14 подключённых USB-узлов, 16 узлов топологии.
- После исправления пустых портов: inventory_complete=true, глобальных ошибок 0.
- 105 блоков дескрипторов; 13624 полей с учётом топологии и повторения свойств
  дочерних функций. Это количество сохранённых строк, не 10 тысяч уникальных API.
- Набор VID/PID с учётом повторяющихся устройств совпал с USBTreeView 4.7.4: 14/14.
- Режимы Low/Full/High/SuperSpeed/SSP совпали: 14/14. На SSP-хабе подтверждены RX/TX 10 Гбит/с.
- Драйвер возвращает ConnectionIndex=0 для пустого порта. Теперь это допускается
  только при NoDeviceConnected; для подключённого устройства неверный индекс отклоняется.
- Нативное окно запущено в интерактивной сессии обычным токеном пользователя.
  Доказательства UI/галочек и итоговый SHA фиксируются в WINDOWS_LAB.md после прогона.
- 38 unit/integration tests, Clippy Linux/Windows, Windows release cross-build проходят.

## Границы полноты

Полный паритет со всеми режимами USBTreeView не объявляется. Реализованы смысловые
декодеры распространённых BOS/UVC/UAC1/2/MIDI1/CDC блоков; [точное покрытие](research/DESCRIPTOR_DECODERS.md).
Неподдержанные версии и подтипы сохраняются исходными байтами. HID Report Descriptor
и MS OS vendor requests недоступны через стандартный Windows hub IOCTL; причина
показана в полях. MS OS string 0xEE читается только после подтверждения поддержки
кэшем Windows osvc. CM notification monitor теперь реализован.

USB4/Thunderbolt protocol analyzer, Bluetooth pairing management, XML import,
restart/eject не входят в готовый read-only сборщик 0.3.0. Заявленное питание
не является измерением. Физическое переподключение в этом прогоне не выполнялось.

Один USB-хаб не отдаёт список языков (Win32 31); это видно как недоступный запрос,
а не скрывается успешным общим статусом. inventory_complete означает завершённое
перечисление, не успешность каждого необязательного запроса.

Сбор ограничен числом узлов/размером ответа; отдельный драйверный вызов всё ещё может
задержаться. На текущем стенде не проверялись физическое переподключение во время
сбора, все модели USB, ARM64 и все DPI. Заключение об исправности кабеля не выдаётся.

## Файлы

- `src/collector/windows.rs`, `enrich.rs`, `property_names.rs`: Windows API и сбор.
- `src/descriptors.rs`, `wire.rs`: декодирование и сохранение исходных данных.
- `src/fields.rs`: поля и независимая маска вывода.
- `src/app.rs`: компактная таблица, панель галочек, настройки.
- `src/report.rs`: выбранные поля в JSON/HTML с отдельной настройкой приватности.
- `usb-doctor-cli --raw --output full.json`: полный локальный снимок; содержит IDs,
  поэтому raw запрещён в stdout и не должен попадать в Git/публичные отчёты.

Live JSON/XML/скриншоты лежат в игнорируемой .scratch/ и в отдельной Windows-папке
UsbDoctorLab. Секреты, ключи, реальные серийники и raw snapshots в репозиторий не добавляются.

## Проверка 0.3.0

На том же Home-PC: 14 устройств, 16 узлов топологии, 13730 полей с учётом повторов,
106 descriptor blocks (в том числе один валидный MSFT100), 607 HID-полей. Сравнение
VID/PID/mode/config lengths с USBTreeView прошло; глобальных ошибок нет.
47 тестов Linux и 48 Windows прошли (дополнительный Windows-тест проверяет цикл
регистрации/снятия PnP). UI Automation подтвердил открытие панели, выключение и
восстановление PID, сохранение настройки и регистрацию PnP.
На стенде нет UVC/UAC/MIDI/CDC конфигураций: их семантика проверена фикстурами,
а не подключённой камерой/аудиокартой. BOS и MS OS проверены живыми ответами.
