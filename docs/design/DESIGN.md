# Понятный USB-доктор: дизайн первой версии

Дата: 2026-09-27. Статус: интерактивный офлайн-прототип, **не Windows-приложение**.

Открыть [prototype.html](prototype.html) в браузере. HTML, CSS и JavaScript локальные,
без шрифтов из сети, сборки, зависимостей, телеметрии и обращения к оборудованию.
Надпись «Демо · пример данных» видна постоянно. Данные полностью вымышлены.

## Продуктовая задача

За одну минуту пользователь должен ответить: какое устройство выбрано, что известно
о подключении, есть ли основание для дополнительной проверки и что сделать дальше.
Технический пользователь должен иметь доступ к исходным полям и ограничениям вывода.

USBTreeView уже сопоставляет USB и Windows-устройства, показывает дочерние диски/COM,
декодирует дескрипторы, ищет устройства, сохраняет отчёты и поддерживает high DPI.
Наша гипотеза преимущества — сокращение усилий на интерпретацию и сравнение,
а не исключительность сбора USB-сведений. Источник: [официальное описание USBTreeView](https://www.uwe-sieber.de/usbtreeview_e.html).
Гипотезу ещё предстоит проверить на пользователях и реальных данных Windows.

## Информационная архитектура

Слева — короткий список устройств с поиском, понятным именем и текстовым состоянием.
Пустые порты не занимают главный экран. Выбранное устройство сохраняется при поиске;
поиск фильтрует только список и не переключает диагностический контекст молча.

Четыре раздела справа:

1. **Обзор:** наблюдаемый факт → цепочка подключения → режим и возможности отдельно
   → возможная причина → следующий шаг.
2. **Сравнение:** инструкция с одним изменением условий, подтверждение того же устройства,
   снимки A/B, различия и пределы вывода.
3. **Журнал:** события только выбранного устройства. Не реконструирует прошлое
   до запуска программы и не обещает узнать причину отключения.
4. **Подробности:** состояние Windows, источник режима, объяснения дескрипторов,
   неизвестные сведения. Раскрывающиеся секции вместо сплошной текстовой простыни.

Цепочка в обзоре — логический путь выбранного устройства, **не полное USB-дерево**.
Полная карта контроллеров, портов и подтверждённых companion-связей остаётся отдельной
задачей реализации; не имитировать физический разъём по одному логическому номеру.

## Визуальная система

| Элемент | Решение |
|---|---|
| Фон | Белый контент; боковая область `#f6f8f8` |
| Текст | `#1d2d35`; вторичный `#586970` |
| Акцент | Спокойный зелёный `#18675c` для действия и выбора |
| Предупреждение | Тёплый светлый фон и текстовая формулировка, без красной тревоги |
| Неизвестное | Серо-голубой фон с буквальным «Недостаточно данных» |
| Шрифт | Системный Segoe UI/system-ui; интерфейс 13–15 px, заголовок 31 px |
| Геометрия | Тонкие разделители, радиус 6–7 px, минимум теней |
| Отступы | Шаги 8/16/24/32; главный контент 54 px на широком экране |
| Компоновка | Две колонки; при ширине ≤1050 px компактнее; ≤700 px список сверху |

Один основной шаг в контексте устройства. Не использовать набор равнозначных плиток,
диагностический «балл здоровья», скорость в виде спидометра или анимацию фиктивного сканирования.
Цвет всегда дополняется текстом. Иконки декоративны; понятность не зависит от них.

## Состояния и переходы

| Сценарий | Наблюдение | Что предлагает интерфейс |
|---|---|---|
| SSD в High-Speed | В примере EX_V2 operating=false, capable=true | Сравнить прямое подключение; не обвинять кабель |
| Клавиатура Full-Speed | 12 Мбит/с; bcdUSB=2.0 | Объяснить нормальный режим; не маркировать как «медленно» |
| Сведения недоступны | Узел есть; скорость/дескрипторы не получены | Показать неполноту; не подменять нулём или ошибкой устройства |
| Телефон отключён | Последний снимок и событие исчезновения | Показать возраст сведений; сравнение недоступно до нового снимка |
| Поиск без результата | Ноль подходящих имён | Понятная пустая выдача; выбранная карточка остаётся |
| Второй снимок SSD | Синтетический режим 5 Гбит/с на другом пути | Показать различие; не объявлять найденную физическую причину |
| Второй снимок клавиатуры | 12 Мбит/с на другом порту | Объяснить, почему отсутствие роста не является проблемой |
| Смена выбранного устройства | Новый локальный контекст | Журнал/сравнение пересчитываются; экспорт закрывается |
| Экспорт | Просмотр JSON → локальное скачивание | `demo: true`, скрытые идентификаторы, ограничения в отчёте |

Сравнения хранятся в памяти страницы отдельно для каждого ID. Перезагрузка сбрасывает
состояние. Никакие действия не перезапускают устройство, порт или драйвер.
В прототипе сравнение не выполняет реальную идентификацию: два примера принадлежат
одной фикстуре. В продукте потребуются поля идентичности и подтверждение пользователя
при неоднозначности, особенно без серийного номера.

## Достоверность формулировок

- «Что известно» опирается на конкретные поля снимка и время наблюдения.
- «Возможная причина» всегда сохраняет альтернативы и неизвестность.
- «Следующий шаг» объясняет, что именно даст новая проверка.
- `bcdUSB` не равен максимальной скорости; режим и возможные режимы — отдельные сущности.
- Код проблемы Windows 0 не доказывает аппаратную исправность.
- Потребление из дескриптора не является измеренным током.
- Событие отключения не объясняет его причину.
- Мбит/с соединения не равны МБ/с копирования.

## Доступность и приёмка UI

Критерии, которые нужно проверять при следующих изменениях и перед Windows alpha:

- Все действия достижимы Tab/Shift+Tab; активация кнопок Enter/Space, раскрытий Enter.
- Видимый контрастный focus ring; после смены панели клавиатурный фокус не теряется.
- Поиск имеет доступное имя, кнопки устройств — текстовое имя и `aria-pressed`.
- Навигация разделов — обычные кнопки с `aria-current`, без неполной имитации ARIA tabs.
- Изменение выбора/снимка объявляется через live region.
- Подробности построены на нативных `details/summary`; экспорт использует текстовый preview.
- При 900 px нет горизонтального переполнения основного интерфейса.
- При увеличении масштаба текст не обрезается; большие имена переносятся.
- Состояния различаются текстом, не только цветом; неизвестное не выглядит аварией.
- Проверить Windows 100/150/200% и экранный диктор отдельно. Браузерный Linux QA этого не заменяет.

На момент создания этого файла интерактивные сценарии реализованы; фактическое
визуальное/browser QA фиксируется отдельно координатором задачи. Проверки оборудования,
Windows API, portable EXE и пользовательское сравнение с USBTreeView не выполнялись.

## Что переносить в приложение

Модель состояний, порядок объяснения, устройство навигации и визуальный язык можно
использовать независимо от UI-фреймворка. HTML-прототип не меняет предварительный
выбор Rust/egui из PLAN.md. Перед окончательным выбором проверить на Windows русскую
типографику, high DPI, клавиатуру, экранный диктор и длинные пути.

Полнота возможностей USBTreeView описывается в исследовании проекта; этот прототип
проверяет основной пользовательский сценарий и не является заявлением о feature parity.
