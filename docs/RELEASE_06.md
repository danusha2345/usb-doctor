# USB Глаз 0.6.0 — скорость, темы и оформление

## Быстрое отображение присутствия

Раньше PnP-событие ожидало 800 мс, следующий кадр мог ждать до 500 мс, затем GUI
дожидался всего полного опроса. Теперь callback сразу вызывает request_repaint.
Отдельный поток получает список присутствующих USB-интерфейсов, хабов и контроллеров
из кэша SetupAPI/ConfigMgr, не открывая USB-хабы и не отправляя IOCTL/дескрипторные
запросы. Изменение списка не ждёт фонового процесса подробного сбора.

Подписки охватывают USB Device, Hub и Host Controller. Резервный cache-only проход —
раз в 2 секунды. Полный фоновой опрос — раз в минуту и после изменения; 150 мс
объединения событий применяются только к подробному сбору, не к появлению строки.
Ответ подробного сборщика, начатого до смены поколения PnP, не применяется; старый
процесс запрашивается к завершению. Подробности не могут вернуть уже удалённый узел.

Пока детали нового узла не получены, неизвестные скорость/порт/адрес остаются «—».
Сведения неизменившихся узлов сохраняются. Неполный быстрый проход не удаляет узлы.
Неудавшиеся/unmapped порты без device interface остаются до полного hub-прохода:
их исчезновение по отсутствию интерфейса не считается доказанным отключением.

## Ускорение полного опроса

PnP inventory сначала читает дешёвые идентичности и родителей. Полный набор Windows
properties/legacy/HID/COM собирается только для USB-ветвей и необходимых предков,
а не для каждого устройства компьютера. Узлы без DriverKey теперь участвуют в
связях и не разрывают цепочку родителей. Каталог дополнительных колонок строится
только при открытии выбора полей; на обычных обновлениях не пересортировываются
тысячи свойств. Таблица виртуализирована, сгруппированные хабы имеют дешёвый kind().

Замер на Home-PC, Windows 11, один и тот же состав 14 устройств/16 узлов:
- быстрый cache-only проход: 1,35–2,73 мс (две серии по пять запусков);
- полный сбор внутри нового CLI: около 572 мс;
- полный CLI с запуском процесса/записью JSON: 0.5.0 — 1153,5 мс, 0.6.0 — 700,6 мс;
- все 17 458 ссылок на поля старого снимка найдены в новом; пропущенных ID нет.

Это локальные замеры с кэшем ОС, а не универсальная гарантия end-to-end задержки
физического подключения. Время перечисления оборудования самой Windows и ответы
конкретного драйвера остаются внешними ограничениями. Специального физического
unplug/replug в этом прогоне не проводилось.

## Интерфейс

- Название и PE ProductName: «USB Глаз», ресурсная иконка и иконка окна с глазом.
  После отклонения первого эскиза выбран промежуточный вариант №1 (синий контур);
  альтернативы сохранены в assets/icon-options.
- Встроенный неизменённый Roboto Condensed с кириллицей, SIL OFL 1.1. Исходный TTF
  и лицензия находятся в assets/. Шрифт не зависит от установленных шрифтов Windows.
- Светлая, тёмная, «Как в Windows»: выбор сохраняется, тема передаётся также нативному
  окну. Цвета подсветки читаются в обеих темах.
- Между строками — полупрозрачные штриховые линии. Высота строки 23 px.
- Вертикальный scrollbar всегда виден; полосы не плавающие, ширина 14 px,
  минимальная длина ползунка 30 px. Обе полосы закреплены на границах видимой области даже при узком окне.
- Колонки переставляются перетаскиванием заголовков, включая первую колонку.
  Граница меняет ширину; порядок и ширины сохраняются. Есть раздельный сброс.
- Убрана строка легенды «подключено / отключено / подсветка». Подсветка — 5 секунд,
  в том числе при загрузке старых настроек с другим сроком.
- «Адрес USB» и «USB Device Address» сведены к одной колонке «USB-адрес».
  Старые настройки автоматически нормализуются; номер порта остаётся отдельным.

У обрезанных ячеек отключена автоматическая подсказка egui: остаётся одна явная.
Заголовок синхронизирован с горизонтальной прокруткой тела и фиксирован по вертикали.
На Windows проверено окно шириной 900 px: обе полосы видны, подсказка одна.

Проверки Windows GUI: три темы, drag reorder, единственная колонка адреса,
сохранённые 5 секунд, один экземпляр окна, ProductName. Отдельный повторный просмотр
после полного сбора: 14 ячеек скоростей и 22 ячейки версий драйвера видны, ошибки нет.
78 тестов Linux, 80 Windows, включая слияние быстрых/полных данных, защиту от
устаревшего ответа, сохранение hub-specific полей, миграцию адреса и порядок колонок.

## Совместимость

Целевой диапазон этой сборки — Windows 10/11 x64. Фактически прогнан Windows 11
build 26120. Отдельного runtime-прогона Windows 10 пока нет. Проверены PE imports:
нет статического GetTempPath2W или других намеренно добавленных Windows-11-only API.
Windows 7/8/8.1 и 32-bit Windows не объявляются поддержанными: текущие стандартные
Rust pc-windows targets требуют Windows 10. Нельзя исправить это одним manifest.

Встроен manifest: asInvoker, supportedOS Windows 10 (используется и Windows 11),
PerMonitorV2 с PerMonitor fallback, longPathAware. Административные права не запрашиваются.
GL renderer сохраняет fallback самого eframe/glutin; при ошибке создания интерфейса
показывается причина, а не тихий выход. CLI не требует графического контекста.
Для ARM64 и старых Windows нужна отдельная сборка и реальные стенды.
