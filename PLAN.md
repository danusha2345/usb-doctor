# План проекта USB-доктор

Статус: 0.2.0 — расширенный сбор и компактный UI с маской полей. Первый Windows-прогон выполнен на Home-PC: 14/14 устройств и режимов совпали с USBTreeView. Полнота по всем API/устройствам ещё не заявляется. См. [IMPLEMENTATION.md](docs/IMPLEMENTATION.md) и [WINDOWS_LAB.md](docs/WINDOWS_LAB.md).
Дата: 2026-09-27. Первая целевая платформа: Windows 11 x64.

Материалы: [полная матрица обнаруженных функций USBTreeView](docs/research/USBTREEVIEW_FEATURE_MATRIX.md), [карта Windows API и ограничений](docs/research/WINDOWS_API_MAP.md), [дизайн](docs/design/DESIGN.md), [интерактивный прототип](docs/design/prototype.html). Прототип использует только вымышленные данные. Границы корпуса: web-страницы и статические ресурсы, 59 конечных пунктов меню; встроенная F1 Help и runtime не проверены.

## 1. Задача и аудитория

Помочь владельцу ПК и мастеру понять подключение USB-устройства: что обнаружено,
как оно подключено, какие ограничения наблюдаются и что проверить дальше.
Отправная проблема: USBTreeView даёт полезные сведения, но их трудно интерпретировать.
Продукт — самостоятельная утилита с понятными объяснениями и сравнением подключений.

Главный сценарий: подключить устройство → открыть карточку → выполнить предложенную
проверку → переподключить через другой порт или кабель → сравнить результаты.

## 2. Принципы интерфейса

- Главный экран: понятные названия устройств, тип, текущий статус, время наблюдения.
- Карточка: «Подключение», «Скорость», «Стабильность», «Windows», «Что проверить».
- Цепочка компьютер → хаб → устройство; техническое дерево раскрывается отдельно.
- Всегда отделять наблюдение, гипотезу и следующий шаг. Неизвестное явно обозначать.
- Подробные VID/PID, интерфейсы и дескрипторы доступны без перегрузки главного экрана.
- Доступные названия могут быть неполными; не придумывать модель по похожему VID/PID.
- Один основной сценарий, русский интерфейс, без аккаунта и рекламы в MVP.

## 3. Состав MVP

1. Перечень контроллеров, хабов, устройств и доступных Windows child devices.
2. Сопоставление устройства с COM-портом или диском, когда это подтверждено ОС.
3. Текущий режим соединения отдельно от возможностей порта и устройства.
4. Состояние Windows, драйвер и доступные problem codes с понятными пояснениями.
5. Журнал подключений/отключений только за период наблюдения приложения.
6. Два снимка: «до» и «после», сравнение пути, скорости, состояний и состава функций.
7. Пошаговый сценарий «Сравнить другой порт/кабель» с ручным подтверждением устройства.
8. Локальный экспорт JSON с версией схемы и читаемого HTML-отчёта.
9. Режим демо на обезличенных снимках для проверки UX на Linux и без оборудования.

Пример объяснения: «Сейчас соединение 480 Мбит/с. Доступные сведения подтверждают
поддержку SuperSpeed. Причина более медленного режима пока неизвестна.
Подключите устройство напрямую к подходящему порту и сравните результат».
Это пример текста, не результат измерения существующего устройства.

## 4. Что не входит в MVP

Это граница первой версии, а не отказ от функциональной глубины. Расширенные возможности распределены по P6–P8 ниже. Полный PD/USB4 protocol analyzer и измерение электрических характеристик требуют отдельного исследования и оборудования.

- Перезапуск портов, удаление/установка драйверов, запись реестра и прошивка устройств.
- Произвольные vendor-команды, USB-захват трафика, собственный kernel driver.
- Измерение реального тока, напряжения или качества сигнала без оборудования.
- Автоматический вердикт «кабель неисправен» по одной низкой скорости.
- Полное декодирование USB Power Delivery, USB4 и Thunderbolt.
- Бенчмарк записи на накопитель, облачная диагностика, автообновление, платёжная система.
- Windows 7, macOS и Linux как целевые диагностические платформы первой версии.

## 5. Предварительная архитектура

Рабочий выбор: Rust + windows-rs для Windows API, egui/eframe для интерфейса.
Это проектное решение для прототипа; точные версии закрепить после API-spike.
Если UI-spike не проходит проверку читаемости/DPI/доступности, пересмотреть UI до разработки.

Планируемые слои (папки создавать при реализации):
- `core`: модель снимка, сравнение и объяснимые диагностические правила, без Windows API.
- `platform/windows`: SetupAPI/Configuration Manager, ограниченные hub IOCTL, события устройств.
- `app`: UI, управление сеансом, отмена, показ неполных результатов.
- `report`: JSON/HTML, экранирование текста, обезличивание и версия схемы.
- `tests/fixtures`: небольшие обезличенные снимки и некорректные ответы.

Поток: сборщик → нормализованный снимок → правила → карточка/отчёт.
Каждое поле хранит источник, доступность и время наблюдения. У вывода есть ID правила,
основания и ограничение; UI не генерирует диагноз свободным текстом через LLM.

Сборщик работает вне UI-потока. Нужны ограничения времени и размера, корректное
завершение при исчезновении устройства, частичные результаты при отказе в доступе.
Блокирующие драйверные вызовы исследовать отдельно; не обещать универсальную отмену IOCTL.
Не опрашивать все class-specific/HID/vendor дескрипторы без необходимости.

## 6. Достоверность и безопасность

- Мбит/с режима соединения не равны МБ/с копирования файлов.
- Версия USB в дескрипторе сама по себе не доказывает максимальную скорость изделия.
- Низкий режим USB 2.0 может быть нормой для конкретного устройства с разъёмом USB-C.
- Причину disconnect без дополнительных данных не приписывать кабелю или питанию.
- Логические и физические порты различать; объединение companion ports подтверждать.
- Без серийника идентичность устройства после смены порта может быть неоднозначной.
- Заявленное потребление в дескрипторе не выдавать за измеренный ток.
- Запуск без администратора — базовый сценарий; недоступные поля помечать явно.
- Серийники, имена ПК и персональные пути скрывать в экспортируемом отчёте по умолчанию.
- Никаких автоматических сетевых отправок. Полный отчёт сохранять только по явному выбору.

| P6. Глубина и автоматизация | Декодеры D01–D12, XML import/export, CLI, clipboard/tree capture, тест чтения, WPD, локальные aliases и экспертные настройки | Реальные fixtures форматов; bounds checks; никакого автоопроса рискованных дескрипторов; benchmark имеет Stop и лимиты |

## 8. Проверки реализации

- Unit: нормализация скоростей, неизвестные поля, идентичность, сравнение, правила.
- Регрессии EX.HighSpeed + EX_V2.SuperSpeedOperating, SSP unsupported, conflicting fields; неизвестное не доказывает узкое место.
- Два одинаковых изделия без серийников; повторённый ContainerID; одно изделие с несколькими функциями.
- Некорректные дескрипторы: bLength=0, усечённые буферы, huge wTotalLength, invalid UTF-16; ограниченный сбор и сохранение partial data.
- Fixtures: составное устройство, отсутствующий серийник, access denied, некорректный размер.
- Аппаратный стенд: USB 2.0 устройство, USB 3.x SSD, хаб, COM-адаптер, камера/гарнитура.
- Сценарии: прямой порт/хаб, USB 2.0 кабель у совместимого SSD, disconnect во время чтения,
  несколько одинаковых устройств, сон/пробуждение, непривилегированный пользователь.
- UI: Windows scaling 100/150/200%, клавиатура, длинные имена, пустой список.
- Сборка/Clippy на Linux не заменяют запуск Windows и аппаратную проверку.
- Команды сборки и тестов: [BUILD.md](docs/BUILD.md); проверки этапа: [IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

## 9. После MVP и проверка спроса

Показать 5–10 пользователям одинаковые реальные сценарии в USBTreeView и нашем приложении. Цели: за 30 секунд найти устройство и режим, за 2 минуты провести сравнение, не путать unknown с поломкой. Это критерии будущего теста, не полученные результаты. Измерять время до верного объяснения и ложные диагнозы. Зафиксировать cold start, idle CPU/RAM, размер portable EXE, поведение при 100+ функциях. Визуальная простота не доказывает малое потребление ресурсов.

P6–P8 сохраняют функциональную глубину: сопоставлять реализованное с IDs матрицы, не закрывать семейство дескрипторов по одному заголовку или фикстуре. F1 Help, неустановленные INI-параметры и промежуточная история остаются пробелами исследования, пока не появится точный корпус. Оплату обсуждать после alpha.

CodeGraph индексирует Rust и JavaScript; это не аппаратная проверка Windows-сборщика. Markdown читать напрямую.
